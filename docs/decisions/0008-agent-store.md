# 0008 面向 agent 的商店：MCP 入口、订单和付款

- 状态：第一阶段实现中（2026-10-11）。入口、订单、定制单先做；价格默认 0，付款留到第二阶段。
- 用户的决定（2026-10-11）：
  - 主要的买家是 agent，它们下单购买需要的 UI。
  - 用币付款，两种都收：以 USDC 定价，用 MOTIF 付有折扣。
  - 开源条目免费；定制和社区作品收费，社区作品作者分成。

## 背景

市场原本是给人逛的：浏览、调参、导出。但现在写前端的大多是 Claude Code、Cursor 这类 agent，它们要的是：
- 按需求找到合适的 UI，看到它的样子；
- 拿到能直接放进项目的代码；
- 没有现成的就请人现做。

站点已经有大部分零件：
- 每个条目有机器可读的清单、shadcn 安装地址和 Skill；
- 工作台本身就是一个能现做 UI 的 agent，产物过同一套检查和编译；
- 合约记录署名和来源。

缺的是给 agent 的入口、订单和付款。

## 决定

### 1. 入口：远程 MCP 服务，同一份工具也开放成 HTTP 接口

- `POST /mcp`：MCP 的 Streamable HTTP 传输，无状态模式（每个请求新建一个服务实例）。Claude Code 用 `claude mcp add --transport http motif <站点>/mcp` 接入。
- `POST /api/agent/<工具名>`：给不用 MCP 的 agent，请求体就是工具的输入。
- `/llms.txt`：用自然语言说明站点是什么、怎么接入、流程和价格。

工具只定义一次（zod），两个入口共用：

| 工具 | 作用 |
| --- | --- |
| `search_ui` | 按需求搜索（标题、摘要、标签、层级和分类的名字），返回价格和海报 |
| `get_ui` | 一个条目的完整信息：参数（范围、默认值）、预设、使用说明、许可证、价格 |
| `preview_ui` | 按指定参数或预设渲染截图，给能看图的 agent 判断合不合适 |
| `get_quote` | 报价：现成条目，或一句话描述的定制需求 |
| `place_order` | 下单。免费的现成条目立即交付；定制单交给工作台的 agent 现做 |
| `get_order` | 查订单状态。交付后附代码文件、shadcn 安装命令和 Skill 地址 |

### 2. 订单

- 订单存成文件（`.data/orders`，`MOTIF_ORDERS_DATA` 可改）。订单号足够长，本身就是凭证，和工作台会话一样。
- 现成条目的订单记下当时的参数，交付的是带参数的代码、`npx shadcn add` 命令和 Skill。
- 定制单：
  - 开一个工作台会话（从起点模板开始；给了 `base` 就从那个条目改起），把需求交给站点的模型。
  - 跑完且通过检查就交付，否则标为失败并附上问题。
  - 同时最多跑两个，多出来的排队。
  - 人可以打开对应的工作台页面看进度、接着改。

### 3. 价格

- 统一按 USDC 定价，以字符串表示的十进制数（避免浮点误差）。
- MOTIF 价格按汇率折算后打折：`MOTIF_STORE_MOTIF_PER_USDC`、`MOTIF_STORE_MOTIF_DISCOUNT`。
- 各项价格：
  - 开源条目：0；
  - 定制单：`MOTIF_STORE_CUSTOM_PRICE_USDC`，第一阶段默认 0；
  - 社区作品：由作者定价，要在投稿流程里加一个价格字段，第二阶段做。

### 4. 付款（第二阶段）

- USDC 走 x402：付费请求返回 402 和付款要求，agent 的钱包付款后带着凭证重试，服务端验证后交付。
- MOTIF 走收款合约：付款时按比例分给作者和金库，合约发事件，站点据此交付。
- 先在本地链和测试网上跑通。主网收款要等境外主体和法律意见：在中国大陆，用加密货币收款属于被禁止的虚拟货币相关业务。见 ADR 0005、0007。

## 第一阶段不做

- 付款和价格大于 0 时的拦截：现在价格大于 0 的订单会停在「待付款」，并说明付款还没开放。
- 买家身份：用订单号当凭证，不需要账户。
- 社区作品定价。
