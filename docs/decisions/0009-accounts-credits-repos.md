# 0009 账号、积分和用户仓库

- 状态：第一阶段实现（2026-11-06），部署在 motifne.net。
- 用户的决定（2026-11-06）：
  - 站点要有自己的账号：GitHub 登录，以及邮箱注册和登录。邮件用 Spacemail（`@motifne.net`）发。
  - 每个用户有自己的仓库，并且能关联 GitHub 仓库：一键把自己的项目导入站点，或者 fork。
  - 用积分使用 AI（工作台接真实模型），卖积分套餐；后续的 MCP 服务里，下载、添加 Skill 和前端内容也要花积分。
- 这推翻了 PLAN.md 里「暂不做用户账号」的范围，也改变了 0008 里「开源条目免费」：见下面第 5 节。

## 背景

到目前为止站点没有用户：工作台会话和商店订单的 id 本身就是凭证，社区身份是钱包地址。
要卖积分、要按人扣 AI 的用量、要让人保存自己的东西，就需要账号和一个真正的数据库。

## 决定

### 1. 数据库：SQLite，用 Node 自带的 `node:sqlite`

- 一个文件：`MOTIF_DB_PATH`，默认仓库根目录下的 `.data/motif.sqlite`；生产环境在数据卷里（`/data/db/motif.sqlite`），每天随社区数据一起备份。
- 为什么不是 Postgres：现在只有一台机器、一个站点进程，SQLite 足够，而且没有新的服务要运维。`node:sqlite` 是 Node 22.5+ 自带的，不用编译原生模块（`better-sqlite3` 在 Docker 和 Windows 上都要编译或下载预编译包）。
- WAL 模式、外键开启。积分相关的写操作都在事务里。
- 表结构有版本号（`PRAGMA user_version`），启动时按顺序迁移。登录相关的表由 Better Auth 自己迁移（同一个文件）。
- 多实例部署时要换成 Postgres：Better Auth 和我们自己的查询都只用标准 SQL，换驱动即可。

### 2. 登录：Better Auth

- 自己实现密码哈希、会话、OAuth 的 state 校验、限流很容易出错；Better Auth（MIT）把这些都做好了，并且直接支持 `node:sqlite`。
- 登录方式：
  - **GitHub**：OAuth App，范围 `read:user user:email`。要把仓库推到 GitHub 时再单独申请 `public_repo`（见第 4 节），登录时不要。
  - **邮箱 + 密码**：注册后必须验证邮箱才能登录；找回密码走邮件链接。密码至少 8 位。
- 同一个邮箱先用邮箱注册、后用 GitHub 登录（或者反过来）会自动合并成一个账号，前提是 GitHub 说这个邮箱验证过（不把 GitHub 设成「可信提供方」，那会跳过这个检查，有被冒名接管的风险）。
- 登录状态下在账号页主动关联 GitHub 时，GitHub 的邮箱可以和账号的不同（`allowDifferentEmails`）：邮箱注册的人大多和 GitHub 用的不是同一个邮箱。
- 会话放在 httpOnly 的 cookie 里。页面本身保持静态：头部的账号按钮在浏览器里取会话，不让每个页面都变成动态渲染。
- 限流用 Better Auth 自带的（按客户端 IP）。Caddy 会丢掉客户端自己带的 `X-Forwarded-For`，只写它看到的地址，所以这个头可信。
- 邮件：SMTP（`MOTIF_SMTP_*`）。没配置时：开发模式把链接打印到终端；生产环境关闭邮箱注册（GitHub 登录照常），页面上说明原因，不让人注册了却收不到验证邮件。

### 3. 用户资料

- 每个用户一个唯一的 `handle`（3–32 位小写字母、数字、短横线），主页是 `/u/<handle>`，仓库是 `/u/<handle>/<仓库>`。
- 第一次登录时自动生成：GitHub 用户名优先，其次邮箱的前半段；重名就加数字。用户可以改，保留字（`admin`、`api`、`market` 等）不能用。

### 4. 用户仓库

- 仓库就是一组文本文件（组件、条目、整个前端项目都行），存在 SQLite 里（`repo`、`repo_file`），随数据库一起备份。
- 限额：每人 50 个仓库；每个仓库 1000 个文件、合计 8 MB、单个文件 512 KB；只收文本文件（按扩展名和内容里有没有 NUL 字节判断），图片、字体、依赖目录（`node_modules`、`.git`、`dist` 等）在导入时跳过并告诉用户跳过了多少。
- 公开或私有。私有仓库只有主人能看到，对别人一律 404（不暴露是否存在）。
- 来源：
  - **新建**：空仓库。
  - **从 GitHub 导入**：列出用户自己的 GitHub 仓库，或者粘贴任意公开仓库的地址。用 GitHub 的 zipball 接口下载默认分支，在内存里解压、过滤。记下来源仓库和提交，之后可以「从 GitHub 同步」。
  - **Fork**：别人的公开仓库，或者市场里的条目，复制一份到自己名下，记下来源（显示「fork 自 …」）。
  - **从工作台保存**：把工作台里做的条目存成仓库（`motif.manifest.json` + 源文件）；这样的仓库可以「在工作台打开」接着改。
- 推到 GitHub：在用户的 GitHub 账号下新建一个仓库，用 Git Data 接口一次提交全部文件。需要 `public_repo` 权限，第一次用时跳到 GitHub 授权。导入自别人 GitHub 的仓库还可以直接在 GitHub 上 fork。
- 在线编辑：主人可以新建、修改、删除文件（CodeMirror）。不做分支、历史和合并：要这些就推到 GitHub。

### 5. 积分

- 积分是整数。每个用户一个余额，所有变动记进流水（`credit_ledger`：变动、变动后余额、类型、关联对象、时间）。余额只能在事务里和流水一起改，任何时候余额 = 流水之和。
- 同一件事只记一次：流水上有 `(用户, 类型, 关联对象)` 的唯一约束（例如同一张订单只到账一次、同一个条目只解锁一次）。
- 价格表只在一个地方定义（`lib/credits/pricing.ts`），环境变量可以改：
  | 项目 | 默认 |
  | --- | --- |
  | 注册赠送（邮箱验证后；同一个收件箱只送一次） | 200 |
  | 解锁一个条目（下载、MCP 交付代码） | 10 |
  | 解锁一个 Skill | 10 |
  | 工作台：每 1000 个输入 token | 1 |
  | 工作台：每 1000 个输出 token | 5 |
  | 定制单（MCP 的 `place_order` 带 brief） | 300 |
- 注册赠送：GitHub 登录的新用户（邮箱是验证过的）当场送；邮箱注册的点了验证链接再送。按规范化的邮箱（小写、去掉 +标签、Gmail 去掉点）只送一次，挡住最省事的刷法。
- 定制单下单时扣积分，做失败（超时、没通过检查、服务器重启）原样退回；服务器没配模型时直接拒绝，不扣。
- **解锁**而不是按次收费：花一次积分，这个条目（或 Skill）以后对这个用户永久免费，网页下载和 MCP 交付共用。重复下载不应该反复扣钱。
- 工作台会话有主人：登录用户开的会话，或者第一个花积分跑 agent 的人认领的匿名会话。之后只有主人能跑 agent、改代码、调参数、回退（别人拿到链接只能看）。
- 工作台按实际用量扣：每一步模型调用回报用量就扣一次，余额扣光时中止这一轮（和 0006 里的会话额度一样的位置）。一轮只记一条流水，跑的过程中更新它的金额。开始一轮至少要有 20 积分。
- 关于「开源条目也收费」：代码本身是 MIT，GitHub 上的仓库、`/r/<条目>.json`（shadcn）和代码视图都还是公开的，积分收的是便利（一键下载完整项目、MCP 直接交付、Skill 打包），不是 DRM。这样既不违反上游许可证，也不让站点的公开 API 突然失效。

### 6. 积分套餐和付款

- 套餐也定义在 `lib/credits/pricing.ts`（人民币定价，以分为单位存整数）：
  | 套餐 | 价格 | 积分 |
  | --- | --- | --- |
  | 体验 | ¥9.9 | 500 |
  | 标准 | ¥39 | 2,200 |
  | 专业 | ¥99 | 6,000 |
  | 工作室 | ¥299 | 20,000 |
- 购买生成一张订单（`credit_order`：待付款 → 已付款 / 已取消）。付款完成时在同一个事务里把订单标为已付款并加积分（流水关联订单号，重复确认不会重复到账）。
- 付款通道还没接：支付宝、微信支付都要商户资质，用户还没定。现在的流程是下单后由管理员在 `/admin` 确认收款；付款通道是一个接口（创建付款、校验回调），接入后把「管理员确认」换成回调确认，其余不变。

### 7. 管理后台

- `MOTIF_ADMIN_EMAILS` 里的邮箱（验证过的）是管理员。`/admin`：确认或取消积分订单、给用户加减积分（必须写原因，记进流水）、查看用户和余额。

### 8. API 密钥和 MCP

- 用户在账号页创建 API 密钥（`mk_` 开头，只显示一次，库里只存 SHA-256），每人最多 10 个，可以随时吊销。
- `/mcp` 和 `/api/agent/<工具>` 读 `Authorization: Bearer <密钥>`：
  - 搜索、详情、截图预览、报价不需要密钥（让 agent 能先逛）；
  - 拿代码（`place_order` 现成条目）、拿 Skill（`get_skill`）要密钥并解锁，定制单按价格扣积分；
  - 新增 `list_skills`、`get_skill`、`get_balance` 三个工具。
- 账号页给出带密钥的接入命令：`claude mcp add --transport http motif https://motifne.net/mcp --header "Authorization: Bearer mk_…"`。

## 风险和以后要做的

- 单进程：工作台运行中的会话、限流计数都在进程内存里；SQLite 也要求只有一个写进程。扩容时一起换。
- 付款通道和发票。
- 积分有效期、退款：现在积分不过期，也不退。
- 用户仓库没有版本历史；需要历史的项目推到 GitHub。
- 社区（链上身份）和站点账号还是两套：以后可以让账号绑定钱包地址。
